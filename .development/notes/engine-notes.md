# Повадки движка

Грабли Essentials v21.1 / RMXP, на которые уже наступали. Всё проверено по исходникам
(секции скриптов указаны) и на практике.

---

## RMXP и игра дерутся за Data/*.rxdata

**Симптом.** Меняешь что-то через дебаг-редактор в игре, сохраняешь — после перезахода
изменений нет.

**Причина.** И RMXP, и игра держат `Data/*.rxdata` в памяти и при сохранении переписывают
файл **целиком**. Кто сохранил последним, тот и выиграл.

**Правило.** Перед любой правкой данных вне RMXP — **закрыть RMXP**. Это касается и
дебаг-редакторов игры, и скриптов из `../tools/`.

## Terrain tags: редактор ограничен 0–7

Номера 0–7 заняты стандартными тегами целиком:

| № | Тег | | № | Тег |
|---|---|---|---|---|
| 0 | None | | 4 | Rock |
| 1 | Ledge | | 5 | DeepWater |
| 2 | Grass | | 6 | StillWater |
| 3 | Sand | | 7 | Water |

Всё, что выше, редактором не выставить: 8 Waterfall, 9 WaterfallCrest, **10 TallGrass**,
11 UnderwaterGrass, 12 Ice, 13 Neutral, 14 SootGrass, 15 Bridge, 16 Puddle, 17 NoEffect.

Способы задать 8+: Debug menu → «Edit terrain tags» (его описание прямо говорит
*Required for tags 8+*) либо скрипт `../tools/apply_terrain_tags.rb`. Отдельный `Editor.exe`
в v21 не нужен, его в проекте и нет.

**Важно:** RMXP при правке тайлсета сбрасывает непонятные ему значения 8+ обратно в 0.
Поэтому теги 8+ проставляются **последними**, после всей работы в редакторе.

## Куст под персонажем: два разных режима

`Game_Character#calculate_bush_depth`:

```ruby
if deepBush?(...)                      # глубокий
  if moving?
    @bush_depth = TILE_HEIGHT if <тайл сзади тоже глубокий>
  else
    @bush_depth = TILE_HEIGHT          # 32 px
  end
elsif bush?(...) && !moving?           # обычный
  @bush_depth = 12
end
```

Обычный куст **гасится при движении** явным `&& !moving?` — наследство ванильного RPG Maker,
где bush задуман под низкие кустики и подрезает только ступни. Глубокий режим Essentials
добавил под покемоновские заросли, там эффект сохраняется.

Оба режима требуют **и** флага у тега, **и** Bush Flag у тайла:

```ruby
return true if terrain.deep_bush && @passages[tile_id] & 0x40 == 0x40
```

Значит декоративная трава без Bush Flag не затрагивается никакими правками тегов.

Флаг `deep_bush` из коробки есть только у `:TallGrass` (10). В проекте он добавлен ещё и к
`:Grass` (2) плагином `Plugins/Deep Grass`, там же глубина для тега 2 переопределена на 12 px
(32 скрывали персонажа почти целиком — кадр спрайта 64 px).

При **входе** в заросли первый шаг персонаж виден целиком: условие требует, чтобы тайл, с
которого шагнули, тоже был глубоким. Это не баг, оригинальные игры ведут себя так же.

## Кэш плагинов не сбрасывается при удалении

**Симптом.** Удалил папку плагина — а он продолжает работать.

**Причина.** `PluginManager.needCompiling?` сверяет mtime файлов только **существующих**
плагинов. Факт удаления не отслеживается, и старый скомпилированный код живёт в
`Data/PluginScripts.rxdata`.

**Лечение.** Запустить игру с зажатым **Ctrl** или **Shift**, либо удалить
`Data/PluginScripts.rxdata`.

Проверить, что реально лежит в кэше:

```bash
ruby -r./.development/tools/rgss_stubs -e 'require "zlib"; load_rxdata("Data/PluginScripts.rxdata").each { |p| puts p[0] }'
```

Сверять кэш с папками **по имени бесполезно** — имя из `meta.txt` законно отличается от имени
папки (`HotFixes` → `v21.1 Hotfixes`). Сверять надо по содержимому скриптов.

## Автотайлы

7 слотов на тайлсет — жёсткий лимит RMXP. Сверх него есть штатный механизм
`TilemapRenderer::EXTRA_AUTOTILES` (заготовка плагина лежит в `../snippets/`).

Формат: `tileset_id => [[большие], [одиночные]]`.

| Тип | Съедает ID | Файл | Автостыковка в редакторе |
|---|---|---|---|
| Обычный слот (1–7) | — | 96×128 на кадр | **да** |
| Большой extra | **48** | 96×128 на кадр | нет |
| Одиночный extra | **1** | 32×32 на кадр | нет |

**Автостыковки у extra-автотайлов нет и быть не может** — она реализована внутри
`RPGXP.exe`, который про этот механизм не знает. Поэтому extra нужны только ради анимации;
всё, что должно автостыковаться, обязано жить в обычных 7 слотах.

Extra-автотайлы перехватывают тайлы **с начала тайлсета** (с ID 384), сначала все большие,
потом все одиночные. Отсюда два следствия:

- под них надо резервировать верхние ряды тайлсета **заранее**;
- добавление большого автотайла сдвигает все одиночные на 48 ID. Поэтому в этом проекте
  решено больших extra не заводить вовсе.

Скорость анимации задаётся суффиксом в имени файла: `water[10].png` → 10/20 = 0.5 с на кадр
(по умолчанию `AUTOTILE_FRAME_DURATION = 5`, т.е. 0.25 с).

## Размеры тайлсета

- ширина **ровно 256 px** — `TILESET_WIDTH = SOURCE_TILE_WIDTH * TILESET_TILES_PER_ROW` (32 × 8), не настраивается
- тайл в исходнике **32×32** — `SOURCE_TILE_WIDTH = 32`, константа
- высота кратна 32
- **держать ≤ 8192 px** (256 рядов, 2048 тайлов): выше включается механизм «мега-текстур»
  `TilesetWrapper.wrapTileset`, который режет тайлсет на колонки. Работает, но это лишняя
  память, а у игроков лимит текстуры GPU может быть как раз 8192

Ряды **снизу дописываются бесплатно** — ID не сдвигаются. Вставка в середину ломает все
карты и списки тегов. Поэтому между тематическими блоками стоит оставлять пустые ряды про
запас.
